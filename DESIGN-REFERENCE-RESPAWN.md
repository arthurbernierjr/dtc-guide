## R0. What the site is now

One site, two halves:

- **The path.** Eighteen weeks, fifty-four sessions, twelve units, in the order of the curriculum master index (Tue / Wed / Sat). Each session is a long-read teaching page written in the studio voice (a 20-minute video on paper: a hook, the idea, the demonstration, where it breaks, your turn). Sessions are published one at a time; a session that is not written yet still has a card on the path, in the designed empty state (§R6).
- **The library.** The existing 226 pages (algorithms, data structures, practice, nine languages, system design, patterns, security, mindset). Unchanged in layout. Every library page that a session points to becomes a **side quest** of that session and says so at the top (§R8).

The name is the logo. The world had magic; the word is crossed out and **AI** is written over it in the margin. That correction appears on the brand lockup everywhere and on the chapter opener of every session page, and nowhere else (§R11).

## R2. The name and the logo

**Full name (as written):** *I Respawned As A Super Coder In A World with ~~Magic~~ AI*. The strike and the correction are part of the name. In running prose the name is written "I Respawned As A Super Coder In A World with AI" (plain text cannot strike). In `<title>` and Open Graph tags it is the plain form.

**Accessible name (every lockup, every size):** `I respawned as a super coder in a world with magic, crossed out, corrected to AI`. Set as `aria-label` on the link or heading that wraps the lockup; the visual pieces inside are `aria-hidden="true"`. Screen readers never hear the markup, they hear the sentence.

**Markup of the correction (the mark):**

```html
<span class="mark" aria-hidden="true"><s>Magic</s><ins>AI</ins></span>
```

- `s` — the word `Magic`, Fraunces italic 500, `opsz 144 · SOFT 60 · WONK 1`, colour `rgb(198 191 196 / .72)` (`--soft` dimmed because it has been corrected), `text-decoration: none` (the browser's line is replaced by the drawn stroke below), `position: relative; display: inline-block; line-height: 1`.
- The **strike** is an inline SVG inserted after the word by the build (not CSS `line-through`): `viewBox="0 0 100 20" preserveAspectRatio="none"`, one path `M3 12 C 25 9, 55 7, 97 9`, `stroke: var(--red)`, `stroke-width: 3.2` (viewBox units, so it scales with the word), `stroke-linecap: round`, `fill: none`. Positioned `absolute; left: -3%; width: 106%; top: 50%; height: .24em; transform: translateY(-46%) rotate(-4deg)`. It reads as one confident marker stroke, slightly rising to the right, slightly past both ends of the word.
- `ins` — the letters `AI`, Clash Display 700, `--yellow`, `text-decoration: none`, size `.56em` of the word, `position: absolute; top: -.46em; right: -.22em; transform: rotate(-8deg)`, `-webkit-text-stroke: .04em var(--bg); paint-order: stroke fill`, `text-shadow: .05em .05em 0 #000`. It sits over the top-right of the struck word like a sticker slapped on a page, the same language as the old `CODE` tilt and the hard shadows.
- Hover on the brand link (desktop, pointer devices, motion allowed): the strike redraws once, left to right, 420ms (`stroke-dasharray / stroke-dashoffset`). Nothing else moves. Off under `prefers-reduced-motion`.

**The four lockups** — every one is HTML text plus the inline SVG stroke; only the exported assets in §R12 are pixels.

- **Code beats** use the existing code panel (label, copy, Run). Run is enabled when the block is a complete program (it prints to a `console.log` panel below, same worker as T-PREP). Fragments are labelled `fragment` and have no Run.
- **Live stages** (DOM sessions, from 2.1 on for HTML that renders and is walked, and from 3.5 on for behaviour): an `html stage=<name>` fence renders as its panel (`<name>.html`, read-only) with the markup mounted *as real DOM* directly under it in a `.stage` box: a dashed mono head `▶ STAGE · <name>.html, rendered · not run yet`, then the stage root (`--surface`, 18/20 padding, form controls styled in the site's own idiom, 36px tall) holding the fence's elements. The matching `js live=<name>` fence gets a **Run live** button; pressing it swaps in a fresh copy of the markup, loads the file as a module script from `/assets/live/path/<slug>/<name>.js` (a script, never from `/assets/src/`, which is text/plain), and the panel under the code becomes the stage's console and keeps logging while the reader clicks and types in the stage. Inside the file `document` means the stage root (selectors, `createElement`, events, `body`), `console` the panel, and `setTimeout` / `setInterval` / `clearTimeout` / `clearInterval` are the real timers with their ids remembered per stage, so pressing Run live again stops anything the previous run left ticking and says so in a dim line (a lesson about timer leaks, not a crash); the build writes that one line at the top of the served file and the page says so in prose. The head reads `live · click, type, watch` in `--green-light` and the box gains a green hairline; an uncaught error turns the head red. A form that submits without `preventDefault()` is stopped at the box and reported in the panel in `--red`, because reloading the lesson is the one thing the stage may not do. Stage markup carries no scripts, handlers, `<style>`, frames or `<h1>` (the build refuses them) and uses only the stage palette: `.card`, `.row`, `.highlight`, `.big`, `.hidden`, `.muted`, `.completed`, `.tag`, `.counter`, `.log` (scrolls past 168px), the game pieces `.square` (52px button), `button.lit` (yellow), `button.win` (green), the text colours `.win` / `.lose`, and the border colours `.easy/.low` green · `.medium` yellow · `.hard/.high` red · `.legendary/.urgent` violet. Chip `N LIVE STAGES` (yellow) joins the meta row; the sitemap row carries `Live stages: n`; the live gate runs every stage in Chromium.
- **Terminal stages** (shell sessions, Unit 1): a `bash term=<name>` fence is written as the reader would type it (no leading `$ `; `#` lines are comments and are shown faint but not run) and renders as its panel titled *you type* with a **Run in terminal** button, and directly under it a `.term` box: a mono head `▶ Terminal · adventurer@newworld · bash · not run yet`, a dark screen (`--code`, 13.5px mono, long lines wrap like a real terminal, scrolls past 420px, empty state *press Run in terminal, or type a command below*), and a real prompt line `adventurer@newworld:~$` with a text input. Pressing the button replays the script line by line with a typing effect (instant under reduced motion), each command in bold after a `--green-light` prompt, output in `--soft`, errors in `--red` with the exact GNU wording (`mkidr: command not found`, `cat: notes.txt: No such file or directory`); when it finishes the head reads `N commands run · now type your own` and the box gains a green hairline, and the reader can keep going at the prompt with ↑/↓ history and Tab completion. The shell is `term.js`, an in-page Bash emulator over an in-memory filesystem (home `/home/adventurer`, no network, no disk): quotes, `$VAR`, `$(cmd)`, globs, pipes, `>`/`>>`/`<`/`2>`, `&&`/`||`/`;`, aliases, executable scripts, and the coreutils a first week needs (`pwd ls cd mkdir touch echo cat head tail wc grep sort uniq cp mv rm rmdir find tree chmod which man --help history clear date cal whoami hostname env export alias nano`, with `node`/`code --version` canned). `git` is real inside the box: a companion file `git.js`, loaded after `term.js`, models init · config · status · add · rm · commit · log (`--oneline --graph --all`) · diff (`--staged`) · show · branch · checkout / switch · merge (fast-forward, three-way with diff3 conflict markers, `--abort`) · restore · reset · stash · remote · push · pull · fetch · clone over an in-memory GitHub, with Git 2.47's own sentences (the `master` hint when `init.defaultBranch` is unset, *Author identity unknown*, *Your local changes … would be overwritten*, `! [rejected] … (fetch first)`). Repositories live on the `.git` node of the box's filesystem and reset with it. The same file supplies the guild hall for Session 1.4: `ssh-keygen` (ed25519, fingerprint and randomart), `ssh-agent`/`ssh-add`, `ssh -T git@github.com` (first-contact host prompt, *Permission denied (publickey)* until the key is on the account, then *Hi adventurer-dev!*), `eval`, `pbcopy`, and GitHub's `gh` CLI (`auth login` as a canned device-flow transcript, `ssh-key add/list`, `repo create/view/clone/fork --clone/list`, `pr create/list/view/merge/checkout`, `browse`) over a per-box GitHub where the reader is `adventurer-dev`, `newworld-guild/quest-board` is seeded and read-only to the reader, pushes to repositories the reader does not own are refused with GitHub's sentence, forks get an `upstream` remote, and a PR from a fork targets the parent and cannot be merged by the reader. Every browser click a session asks for (New SSH key, New repository, Fork, Compare & pull request, Merge pull request) therefore has a command in the box that does the same thing, and the prose says so each time. Each box keeps its own filesystem; Run in terminal resets it so the replay is the same every time. A fence tagged `may-fail` is a Where-it-breaks terminal that is allowed to hit `command not found` on purpose. Chip `N TERMINALS` (yellow) joins the meta row; the runnable chip is dropped when the page has terminals and no worker files; the sitemap row carries `Terminals: n`; the live gate replays every terminal in Chromium (every line ran, nothing unintended was `not found`, a typed command answered, run twice).
- **The failure beat** is a `.callout.dont` (red left rule, `--red` title `WHERE IT BREAKS`), containing the broken code as a panel and the console output as a second panel with the error line in `--red`.
