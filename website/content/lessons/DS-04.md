## The idea

Picture a stack of cafeteria trays next to a lunch line. You take the tray on top. That is last in, first out. In the lunch line, the person who arrived first gets served first. That is first in, first out.

A stack is the tool for nesting and for the most recent thing you have not finished. A queue is the tool for order and for walking level by level. Push and pop are O(1). A monotonic stack is O(n) for the whole array, because each index is pushed once and popped once. In JavaScript, `Array.shift()` is O(n), so a real queue advances a head index or uses a ring, and it does not pull from the front of a raw array.

The tray stack remembers openers, operators, and folder names until the matching closer shows up. If the top tray is the wrong shape, the nesting is broken. A min stack keeps a second stack of running minimums, so "what is the smallest so far" is a peek, still O(1).

A monotonic stack is fussier. It holds indices whose values stay in sorted order, decreasing if you want the next greater item. When a taller value arrives, every shorter index on top just found its answer, and you pop them. Leftovers have no next greater. Flip the comparison for next smaller. Walk from the right if you want the previous one.

A queue can be two stacks. Push into the inbox. Pop from the outbox. When the outbox is empty, pour the inbox over, which reverses it, so the oldest item lands on top. Each item moves at most twice, so a run of operations is amortized O(1) each.

## Why it matters

Reach for a stack when the problem says balanced, matching, nested, undo, or evaluate. Parentheses, file paths, and reverse Polish notation are the same move: push the thing you cannot finish yet, and finish it when its partner arrives. Reach for a queue when the problem says first in first out, or level by level. Breadth-first search is a queue. The thing you discover first is the thing you expand first, which is why an unweighted shortest path falls out of it.

The phrase "next greater," "span," "daily temperatures," or "largest rectangle" means a monotonic stack. A nested loop that looks backward from every index is O(n²). The stack throws that inner scan away, because each index joins and leaves once.

You already keep this kind of pile. The back button is a stack of pages. A printer line is a queue. The bug people ship is calling `shift()` inside a hot loop and calling it O(1). It walks the whole array every time. The sheet's plain queue and its ring buffer both keep the ends O(1).

Two stacks make a queue in amortized O(1). One queue makes a stack if each push rotates the older items to the back, and that push is O(n).

## A small example

```javascript
function nextGreater(nums) {
  const answer = new Array(nums.length).fill(-1);
  const stack = [];
  for (let i = 0; i < nums.length; i++) {
    while (stack.length > 0 && nums[stack[stack.length - 1]] < nums[i]) {
      answer[stack.pop()] = nums[i];
    }
    stack.push(i);
  }
  return answer;
}

const greater = nextGreater([2, 1, 2, 4, 3]);
```

`greater` is `[4, 2, 4, -1, -1]`. The stack held indices, not copies of the values. Each index was pushed once.

## What the code below is doing

Section 1 checks parentheses. Push openers. On a closer, the top must be the match. Empty at the end means balanced. O(n) time and space. Section 2 is the min stack: a parallel stack of running minimums, so push, pop, top, and getMin are all O(1). Section 3 evaluates reverse Polish notation. Numbers get pushed. An operator pops `b`, then `a`, and pushes `a` operated with `b`.

Section 4 decodes strings like nested repeats. One stack holds counts, one holds the string so far. On `]` you pop and repeat. Section 5 simplifies a Unix path. Split on `/`. `..` pops. `.` and empty pieces are skipped. Section 6 builds a queue from two stacks, inbox and outbox, amortized O(1). Section 7 builds a stack from one queue: after push, rotate `size - 1` times so the new item sits at the front. Push is O(n), pop is O(1).

Then the monotonic template: stack of indices, values decreasing, pop while the new value is greater, record the answer as a value or as a distance, push the index. Section 8 writes the next greater value, and a second lap over the same array is how you handle a circular list. Section 9 writes the distance until a warmer day. Section 10 is the largest rectangle in a histogram. The stack stays increasing. On a pop, the width is `i - stackTop - 1`, and a sentinel 0 at the end flushes the stack. Section 11 removes k digits to leave the smallest number: pop while the top is bigger than the new digit and you still have removals left, then strip leading zeros.

Section 12 is a circular queue, a fixed array with head and tail moving mod the capacity. Every operation is O(1), and the space is the capacity. Section 13 is the everyday JavaScript queue: an array plus a head index. Dequeue advances the head. Compact occasionally if the dead prefix gets long. Amortized O(1), and `shift` stays out of it.

When you talk about it, say this: a stack is the most recent unfinished thing, a queue is first in first out, both ends are O(1), and a monotonic stack is O(n) because each index is pushed and popped once.
