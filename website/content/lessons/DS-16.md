## The idea

Picture a subway map. The dots are stations. The lines between them are tracks. Some tracks run one way. Some have a travel time written on them. You can ride every station, decide which station has to be built before another, glue stations into groups, or look for the cheapest ride.

A graph is nodes plus edges. You traverse it with breadth-first or depth-first search in O(V + E), order a directed graph with a topological sort, connect components with union-find at about O(α(n)) per operation, and find shortest paths with Dijkstra in O((V + E) log V) when every weight is non-negative, or with Bellman-Ford in O(V · E) when a weight can be negative.

Breadth-first search uses a queue, so the first time you reach a station is the fewest hops. Depth-first search uses a stack and finishes one branch before it starts the next.

A visited set keeps both walks finite. Directed cycle checks use three colors: white unseen, gray on the current path, black finished. An edge into a gray node is a cycle. Undirected, a visited neighbor is a cycle only when it is not the parent you just stepped from.

## Why it matters

The words are edges, connected, prerequisites, shortest path, islands, can reach, cycle, minimum spanning tree, and turning one word into another. Prerequisites are a directed graph, and a topological order is a legal build sequence. If the order comes out short, some nodes never reached in-degree zero, and the leftover is a cycle: the courses cannot be finished.

Shortest path forks before you write code. Unweighted means breadth-first search. Non-negative weights mean Dijkstra. A negative weight means Bellman-Ford, because a heap can close a node before a cheaper path arrives.

## A small example

```javascript
function componentCount(n, edges) {
  const graph = Array.from({ length: n }, () => []);
  for (const [u, v] of edges) {
    graph[u].push(v);
    graph[v].push(u);
  }
  const seen = new Set();
  function walk(u) {
    seen.add(u);
    for (const v of graph[u]) if (!seen.has(v)) walk(v);
  }
  let count = 0;
  for (let i = 0; i < n; i++) {
    if (!seen.has(i)) { walk(i); count++; }
  }
  return count;
}

const groups = componentCount(5, [[0, 1], [1, 2], [3, 4]]);
```

`groups` is 2. One walk covers 0, 1, and 2. The next walk starts at 3 and picks up 4. Each new start is a component.

## What the code below is doing

Section 1 builds the adjacency list. Undirected is the default, so each edge is stored twice. Pass `directed` to store it once. Pass `weighted` and each neighbor is a pair `[neighbor, weight]`. O(V + E).

The breadth-first template is a queue, a visited set, and a parent map. The first visit is the shortest hop-count. Walk parents from the target back to the source and reverse. Section 2 is that template as a function, O(V + E) time and O(V) space. The queue dequeues with a head index so removing the front stays O(1). Unreachable returns an empty path.

The depth-first template is recursive (mark, then visit unseen neighbors) or iterative (a stack, skip what you have marked, push the neighbors). Section 3 writes both and records visit order. Section 4 counts connected components in an undirected graph: start a search from every unvisited node, and the number of starts is the number of components. Section 5 treats a grid as a graph. Four directions, and visiting land sinks it to `'0'` so you do not need a separate visited set. Time is O(m · n). Section 6 clones a graph. The map from original node to copy is also the visited set, so a cycle does not clone forever.

Section 7 detects a directed cycle with the three colors. A neighbor that is gray means a back edge. Section 8 detects an undirected cycle: a visited neighbor that is not your parent. Both are O(V + E).

Section 9 is Kahn's topological sort. Count in-degrees, queue every node at zero, pop it, and decrement its neighbors, enqueueing any neighbor that hits zero. If the result is shorter than n, the graph has a cycle and the function returns an empty order. Course schedule is "is the length n," after you point each edge from the prerequisite to the course. Section 10 is the depth-first version: push a node after its descendants, then reverse. A gray neighbor throws, and the catch returns an empty order.

Section 11 is Dijkstra for non-negative weights. A min-heap of `[distance, node]`. When you pop a pair whose distance is worse than the best already stored, that entry is stale and you skip it. O((V + E) log V). Section 12 is the Bellman-Ford sketch. Relax all edges V - 1 times. A further improvement means a negative cycle. O(V · E).

Section 13 is union-find: path compression, union by rank, about O(α(n)) per operation. Section 14 is Kruskal, sorting edges and keeping one when its ends sit in different components, O(E log E). Section 15 two-colors every component. The same color on both ends of an edge means the graph is not bipartite. Section 16 is a word ladder, an implicit graph of words one letter apart, breadth-first by level, O(N · L · 26).

When you talk about it, say this: breadth-first and depth-first are O(V + E), Dijkstra needs non-negative weights, Bellman-Ford tolerates negative weights in O(V · E), and union-find merges groups in nearly constant time.
