## The idea

Picture a family tree drawn on a big sheet of paper. One person at the top, the root. Each person can have people hanging under them. You can point at anyone and talk about their parent, their children, their siblings, and the little tree that hangs from them, the subtree.

A binary tree gives each node at most two children, left and right. A binary search tree keeps every value in the left subtree smaller than the node, and every value in the right subtree larger, so an inorder walk comes out sorted. Walking every node is O(n) time and O(h) stack, where h is the height. Search, insert, and delete on a binary search tree are O(h): O(log n) when the tree stays balanced, and O(n) when it degenerates into a linked list. AVL and red-black trees are the names that keep h at O(log n). Name them. Building one is a different assignment.

Depth counts edges from the root down to a node. Height counts edges from a node down to its deepest leaf. A level is depth plus one. Full means 0 or 2 children. Complete fills left to right. Perfect puts every leaf at the same depth. Balanced means the two subtree heights differ by at most 1 everywhere.

Preorder visits node, left, right. Inorder visits left, node, right. Postorder visits left, right, node. Breadth-first search visits a level at a time. The lowest common ancestor is the deepest node that still covers both targets. Diameter is the longest path, in edges. Horizontal distance is how far left or right of the root a node sits.

## Why it matters

Trees show up whenever one thing contains other things: a folder, a comment thread, a decision. The binary search tree finds, inserts, and deletes in O(h) and hands you sorted order for free, because inorder is sorted.

Checking a node only against its own children accepts a tree that breaks further down. Carry a low bound and a high bound into every call. The left child inherits the parent's value as its new high. The right child inherits it as its new low.

The call stack of a recursive walk is O(h). A skinny tree has h = n. Section 2 on the sheet puts the same three orders on an explicit stack.

## A small example

```javascript
function isValidBST(node, lo = -Infinity, hi = Infinity) {
  if (!node) return true;
  if (node.val <= lo || node.val >= hi) return false;
  return isValidBST(node.left, lo, node.val) && isValidBST(node.right, node.val, hi);
}

const tree = {
  val: 5,
  left: { val: 1, left: null, right: null },
  right: { val: 4, left: { val: 3, left: null, right: null }, right: { val: 6, left: null, right: null } },
};
const ok = isValidBST(tree);
```

`ok` is false. The node 3 sits under 5's right side, and 3 is smaller than 5. Comparing 4 only with its own children would have waved that through.

## What the code below is doing

Section 0 turns a level-order array into a tree and back. Nulls are holes. Section 1 is recursive preorder, inorder, and postorder, O(n) time and O(h) stack. Section 2 is the same three walks on an explicit stack: preorder pushes right first, inorder exhausts left then steps right, postorder is a reversed modified preorder. Section 3 is level order, O(n) time and O(w) at the widest level, plus zigzag.

Section 4 is the views. Right side is the last node of each level, left side the first. Vertical buckets group by horizontal distance in breadth-first order. Top view keeps the first value in a column, bottom view the last, vertical order the whole column. Boundary goes anticlockwise: root, left edge without leaves, leaves left to right, right edge upward without leaves.

Section 5 measures, all O(n): max depth, min depth (a one-child node is not a leaf), count, sum, diameter as best left-height plus right-height in edges, and balanced via a `-1` sentinel. Section 6 is invert, same tree, symmetric as one side against the mirror of the other, and subtree, O(n · m) by checking sameness at every node. Section 7 is root-to-leaf sum, all paths by push and pop, and max path sum, keeping the bend through the node and returning only the better arm.

Section 8 is the general lowest common ancestor. A node counts as an ancestor of itself. From section 9 the sheet is a search tree and duplicates are ignored, so say which side they would take if a spec allows them. Section 9 is search, insert, min, and max, each O(h), and inorder comes out sorted. Section 10 deletes a leaf or one child by returning the surviving child, and two children by swapping in the inorder successor. Section 11 is the bounds check. A strictly increasing inorder is the other correct test.

Section 12 spends the sorted inorder. Kth smallest stops at k. The successor is the last node where the walk stepped left. Closest keeps the best distance on the search path. Range sum prunes a subtree that sits outside the window. Two-sum walks the inorder array from both ends. The search-tree ancestor walks down while both targets share a side. Section 13 builds a balanced tree by taking the middle of a sorted array, O(n). Section 14 rebuilds from preorder plus inorder, and the left subtree is built first. Postorder plus inorder takes the root from the end and builds the right side first. Section 15 serializes preorder with `#` for null. Section 16 flattens by visiting right, then left, then stitching. Section 17 loops over `children` for an n-ary node.

When you talk about it, say this: inorder of a binary search tree is sorted, search and update cost O(h), and a balanced tree keeps h at O(log n).
